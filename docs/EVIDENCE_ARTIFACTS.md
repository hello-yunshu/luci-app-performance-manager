# Audit evidence artifact classification

This repository generates audit files in three classes. The distinction matters
because a generated file must not be mistaken for release authority.

## 1. Must-commit source-audit snapshots

These are generated by `make audit`, reviewed, and committed. They are the
checked-in source-audit snapshot for a specific audited source commit.

- `docs/FINAL_AUDIT.json`
- `docs/FINAL_AUDIT.md`
- `docs/source-audit.json`

`FINAL_AUDIT.json` and `source-audit.json` contain the same payload.
`FINAL_AUDIT.md` is the human-readable rendering. The snapshot is source-only
and non-promotable; CI artifacts for the same commit remain authoritative for
functional-integration and Stable decisions.

## 2. Committed regenerable inputs

These are rewritten by `make audit` and consumed by tests, later audit steps, or
CI artifact upload. They are committed so a checkout can run `make test` and
review the exact inputs used by the snapshot, but they are not independent
release evidence.

- `docs/SOURCE_GATES.json`
- `docs/HOST_SYNTAX_REPORT.json`
- `docs/RESOURCE_BUDGET.json`
- `docs/rill-integration-status.json`

They may be regenerated at any time with `make audit`; a diff means the source
or tooling changed, not that the artifact is hand-edited evidence.

## 3. Ignored build and local outputs

- `dist/` — `make package` staging directory, ignored by `.gitignore`.
- `local-evidence/`, `local-artifacts/`, `.portable-rootfs/`, `tools/docker-validate/build/` —
  run-specific local validation outputs, ignored by `.gitignore`.

## Commit identity policy

`pmCommitSha` is the **audited source commit**, resolved by `scripts/final_audit.py`:

1. Read the real `git rev-parse HEAD` at the start of the audit.
2. Refuse to write any snapshot when tracked source files are dirty. Generated
   audit files in the list above are excluded from that dirty check, because
   the audit rewrites them itself.
3. If `HEAD` is a snapshot-only commit (a commit whose changed paths are all in
   the generated-audit list), walk to its parent and identify that source
   commit. This avoids the Git self-reference problem: a commit cannot contain
   its own SHA, so the snapshot commit is necessarily a child of the source
   commit it describes.
4. Re-check that `HEAD` did not change during generation.

Therefore the invariant is: **the snapshot identifies the source commit it was
generated from**, and re-running `make audit` after committing the snapshot is
byte-identical because the snapshot-only child is skipped.
