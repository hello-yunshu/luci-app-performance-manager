# Rill Shadow Learning Model — 1.0.2

Performance Manager owns the consumer-specific adapter at `integrations/performance-manager-rill-adapter/`. It links exact crates.io `rill-ml` 1.5.3, reports adapter version 1.0.2, preserves `pm-rill-shadow` protocol v1 and state schema 1, and is verified by Cargo plus real OpenWrt rootfs jobs. RillML v1.5.1's shipped adapter remains a historical fixture only; the upstream PM adapter active surface was removed in RillML 1.5.2 and current PM provisioning never uses that Release asset.

Since 1.0.0-rc.8 every status/observe/outcome response is validated for exact contract, protocol, request ID and operation payload. A successful Observe registers a TTL- and boot-bound **decision binding** keyed by `decisionId`; unexecuted bindings remain in runtime memory only. Entering the declared safe-direct or benchmark execution path freezes that exact binding into the existing durable transaction/session journal. Manual execution never consumes a same-action Rill decision, and a later Observe cannot rebind an active session. Outcome success requires `ok:true` and `accepted:true`; transport/retryable failures retain the binding, while `duplicateFeedback` is reconciled only after the same fingerprinted attempt recorded response loss.

Rill runs as the dedicated unprivileged `performance-manager-rill` service over a bounded Unix-domain socket. The implemented access-control boundary is the service-owned `/run/performance-manager` directory with mode `0750`; root Core can connect, while an unrelated ordinary user cannot traverse/connect. The upstream adapter does not provide a peer-credential gate or a contractual socket inode mode. Rill cannot execute commands, write UCI/sysctl/firewall state or call the Action actuator. Missing, unreachable, malformed, or incompatible Rill remains fail-closed.

The Shadow engine tracks capability/topology/path/route drift, reconstructs validated outcome statistics after restart, applies measurement-quality weights (`controlled_ab` > `passive_before_after` > `health_only`), and exposes advisory output only after a minimum sample count and positive mean reward.

Pinned Rill v1.5.3 persists after every successful Observe and every successful Outcome; the retained v1.5.1 adapter snapshot in `contracts/upstream/rill-pm-adapter-v1.5.1-contract.json` is historical compatibility evidence only. Core therefore never calls Observe from periodic telemetry or read-only diagnostics. It exposes logical counters (`rillObserveAccepted`, Outcome counters, and inferred `expectedAdapterPersistenceEvents`) explicitly labelled as inferred—not physical flash-block writes. The 24-hour gate treats missing measurements as `BLOCKED`, checks both processes, restart counts, state bounds, and requires zero idle Observe/persistence deltas.

The protocol rejects oversized/timeout/invalid messages, unsupported contract/protocol versions and unvalidated outcomes. Filesystem directory permissions—not the wire protocol—exclude unauthorized local users.

A Rill recommendation carries `authority: advisory-only` plus a Core-resolved execution kind. A safe-direct advisory may enter only the existing safe transaction path; a benchmark advisory may enter only `benchmark_start` with explicit controlled Companion evidence. Rill itself has no mutation authority.
